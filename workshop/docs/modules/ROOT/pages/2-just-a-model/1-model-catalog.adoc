= Deploy a model from the model catalog

[role="_abstract"]
Now that you have a project, deploy a model into it.

== Procedure

. Navigate to *AI hub* -> *Models* in the left sidebar.

. You have a choice between with or without accelerator (also known as GPU). +
Search for the following model in the search field and click the tile that appears. +
*With Accelerator:*
+
[.lines_space]
[.console-input]
[source,text]
----
Llama-3.2-3B-Instruct-quantized.w8a8
----
+
*Without Accelerator:*
+
[.lines_space]
[.console-input]
[source,text]
----
Qwen2.5-1.5B-quantized.w8a8
----
+
image::2-just-a-model/model-tile.png[Model Tile for Llama 3.2 3B Instruct]
+
This tutorial uses a small quantized model so it is compatible with more hardware options.
+
NOTE: If you don't see the model, you may need admin access to add it. +
Not sure if you have admin access?  +
Check the left navigation menu: if you see a *Settings* item, you're an {productname-short} admin and can add it yourself. If you don't see *Settings*, ask your cluster administrator to add it, or choose a similar model that's already available. +
To add it yourself: go to *Settings* -> *Model resources and operations* -> *Model catalog settings* and add a new source with the organization *RedHatAI*. Note that this may take a while to load as it syncs a large number of models.
+
image::2-just-a-model/model-catalog-settings.png[Model catalog settings showing RedHatAI organization]
+
After you click the tile, you can see the *Model Card* for the Llama model. This contains information such as how it's built, what license it has, and how to use it.

. Click the *Deploy model* button to start the deployment process for your model. It takes you through three pages in the deployment wizard. Fill in information accordingly.

. In *Model details*, select *Use legacy deployment method* if you have the option, otherwise leave everything as is.
+
image::2-just-a-model/model-details-form.png[Model Details Form]

. In *Model deployment* you have two options, either with or without accelerator. +
For a smoother experience in this workshop, deploy with an accelerator if one is available.
+  
[tabs]                                             
====
With Accelerator::  
+
--
. Select your Project.
. In the *Hardware profile*, select a profile that you can use to deploy on an accelerator, such as a GPU.
. Click *Customize resource request and limits* and ensure you have one accelerator requests and limits, and at least 2 Cores CPU and 8 GiB Memory.
. Under *Deployment resource*, select *Manual selection* and the runtime *vLLM NVIDIA GPU ServingRuntime for KServe* (for Nvidia GPUs, or related for other accelerators) from the dropdown.
+
image::2-just-a-model/model-deployment-form.png[Model Deployment Form]
--                                         

Without Accelerator::
+
--
NOTE: If you don't have an accelerator, your performance will depend heavily on the type of CPU you have and how much resources you can give the model. +
In some cases the response time will be too slow to be usable, in which case consider choosing a smaller model such as *Qwen2.5-1.5B-quantized.w8a8*. +
However, a smaller model might not be viable for the later chapters like xref:5-rag/1-rag-in-playground.adoc[5.1. RAG in the playground] or the entire xref:6-tools-agents/index.adoc[6. Tools and agents] section.

. Select your Project.
. Click *Customize resource request and limits* and ensure you have at least 10 Cores CPU and 16 GiB Memory.
. Under *Deployment resource*, select *Manual selection* and the runtime *vLLM CPU (x86) ServingRuntime for KServe* from the dropdown.
+
image::2-just-a-model/model-deployment-form-cpu.png[Model Deployment Form CPU]
--
====
. In *Advanced settings*:
.. Select the *Publish as AI asset endpoint* option (and optionally enter a Use case).
.. Select *Add custom runtime arguments* under Configuration parameters and enter the following arguments, one per line:
+
[.lines_space]
[.console-input]
[source,text]
----
--enable-auto-tool-choice
--tool-call-parser=llama3_json
----
.. (If using CPU deployment) Select *Add custom runtime environment variables* under Configuration parameters, click *Add variable*, and enter `VLLM_CPU_KVCACHE_SPACE` in the name field and `8` in the value field.
.. Leave the rest as is.
+
image::2-just-a-model/advanced-settings-form.png[Advanced Settings Form]

. Finally, review all the information and verify it is accurate. If all looks good, click *Deploy model*.
+
image::2-just-a-model/review-form.png[Review Form]

== Verification

After deploying the model you will automatically be navigated to the model deployments page. The model should get deployed after a few minutes and you will see that it's Ready in the Status column. 

During this process the model will download to disk, load into active memory (RAM or vRAM), and start running based on the runtime (vLLM in this case). Once it's running, it's served in a similar fashion to a webserver, and ready to receive requests to reply to.

image::2-just-a-model/model-ready.png[Model is Ready]
