= Set up tracing with MLflow

[role="_abstract"]
With MLflow tracing, you can collect inputs and responses to the model, as well as any intermediate steps added (as you will see in later chapters). +
This provides a history of user interactions and model responses, which you can use to test and improve your AI systems. +
You send requests to the model with MLflow tracing enabled, and see how they are collected.

== Prerequisites

- A model has been deployed as described in xref:2-just-a-model/1-model-catalog.adoc[2.1. Deploy a model from the model catalog]
- A workbench has been set up as described in xref:3-move-to-code/2-workbench.adoc[3.2. Create a workbench]

== Procedure

. Return to the workbench (through your AI Project if you have closed it) and open the notebook called `1_mlflow_request.ipynb`. +
This notebook will guide you through how to set up a connection with MLflow and enable tracing to collect information from requests being sent by that notebook.
+
NOTE: You need to enable tracing in all applications you want to appear in the trace. In this case, you enable it from within your Python code.

. Go through that notebook and then return here to examine the MLflow UI.

== Verification

. After the notebook has finished running, return to the OpenShift AI dashboard and select *Develop & train* and then *Experiments*

. Make sure you are in the right project. You should see an experiment called *hospital-helpdesk*. Click *hospital-helpdesk*.
+
image::4-observability-tracing/click-experiment.png[Click the experiment]

. You will now see an overview of your MLflow tracked requests in this experiment. You can browse it. The specific traces are more useful, so select the *Traces* section.
+
image::4-observability-tracing/experiment-overview.png[Experiment overview]

. This is a list of your traces from the requests you made in the notebook. You should have five in total. Click the top one to get more details.
+
image::4-observability-tracing/traces.png[Traces]

. A trace provides a variety of information, such as the system prompt, the input, the output, and any metadata. +
You also have a *Details & Timeline* tab at the top to get a detailed view of each step in the trace and how long each took, which is useful when you have more complicated flows like agentic workflows. +
+
image::4-observability-tracing/trace-info.png[Trace info]

. Optional: Click *Show Assessment* to add *Feedback* and *Expectations* to the trace. You can then add this trace to a dataset by clicking *Add to dataset*. Use the dataset to evaluate other models or system prompts to see if they behave according to your *Expectations*. This provides an easy way to build an eval dataset from your traces.
+
image::4-observability-tracing/show-assessment.png[Show Assessment]
